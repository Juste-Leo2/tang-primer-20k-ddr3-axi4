# Bug report — 02/10/2026 18h20 — Contrôleur DDR3 128-bit SpinalHDL

Contexte : contrôleur DDR3 BL8 128-bit (`Ddr3ControllerCore.scala` + `GowinDdr3Phy.scala`)
vs baseline `nand2mario` (`src/ddr3_controller.v`), vérifié contre modèle Micron
(`simulation/tb_spinal.log`, `tb_orig.log`) et preuves formelles SymbiYosys/Boolector
(`ddr3/test/formal/`).

Image mentale : un train de 8 wagons (8×16 bits) passe devant une porte. Il faut
ouvrir la porte pendant TOUT le passage, puis ranger chaque wagon dans la bonne case.

---

## Bug 1 — `init_done` collé à 1 après un reset (GRAVE, corrigé)

- **Symptôme** : preuve formelle P5 (`init_done → wlevel_done && rcalib_done`)
  violée à BMC step 222 (trace : `init=1` avec `wlevel=rcalib=0` après re-reset).
- **Cause (double)** :
  1. La branche reset ne remettait jamais `init_done_latched` (ni `rburst_seen`) à 0.
  2. Plus subtil : Spinal émet le `if(reset)` en PREMIER dans le `always`, donc le
     `when(...){init:=True}` du bloc status **écrasait le reset** quand les deux
     coïncidaient (priorité inversée).
- **Effet HW** : après un reset en cours de vie (bouton, perte DLL), le SoC croit la
  mémoire prête pendant la recalibration → trafic non calibré → **corruption silencieuse**.
- **Fix** (`Ddr3ControllerCore.scala`) : `init_done_latched := False` (+ `rburst_seen := 0`)
  dans la branche reset, ET garde anti-reset sur le chemin set :
  `when(rst_lock_n && !isResetActive && !busy && IDLE && wlevel && rcalib)`.

## Bug 2 — Registres du bus non parqués au reset (moyen, corrigé)

- **Symptôme** : preuve formelle P9 (`dqs_oen == 0xF` hors fenêtres de drive) violée :
  après un reset en pleine calibration, `dqs_oen` gardait `0000` (drive) au lieu de Hi-Z.
- **Cause** : la branche reset ne parquait pas `dq_oen/dqs_oen/dqs_out/dm_out/dq_out/dqs_read/dqs_hold`.
- **Effet HW** : masqué en pratique (les primitives OSER Gowin ont leur propre reset),
  mais fenêtre de drive sale d'un cycle dans le modèle formel — et piège pour toute
  évolution du PHY.
- **Fix** : parking explicite à Hi-Z (`dq_oen/dqs_oen := 0xF`, etc.) dans la branche reset.
  Mêmes valeurs que les defaults cycliques → zéro changement fonctionnel nominal.

## Bug 3 — Fenêtre de capture DQS trop tardive/étroite (EN COURS)

- **Symptôme** : lectures 128-bit partielles. D'abord `xxxx` total (8 erreurs/8),
  puis 2 beats sur 8 après déplacement de la fenêtre.
- **Cause prouvée (VCD + modèle `prim_sim_tb.v`)** : `dqs_en (= DQSIN & enable)` s'ouvre
  ~3 ns après le début de la rafale → les beats 0,1 sont avalés, seuls 2–3 fronts
  atteignent `DQSR90` → `WPOINT` n'avance que de ~3 crans → `dq_in` partiel + stale.
  Le verrouillage sur `RBURST` (strobe-detect) valide « quelques fronts passent »,
  pas « les 8 beats sont capturés » — suffisant pour l'ancien design (1 beat lu en
  slot 4), insuffisant pour du BL8 128-bit.
- **Preuve de compréhension** : seed de sweep (1,6)→(1,0) = verrou double-hit à (1,1)
  au lieu du faux verrou (2,0), et les beats capturés glissent de (2,3) vers (0,1)
  comme calculé. La fenêtre se pilote bien via `(rclkpos, rclksel)`.

## Options pour le bug 3

### Option 1 — Changer le point de départ du sweep (ex : seed (0,0))

- Coût : 1 simu (~15 min), zéro risque.
- Problème : on cherche une fenêtre par chance d'alignement. Fragile à la moindre
  modification (timing, carte, densité mémoire, température en HW). **Non viable long terme.**

### Option 2 — Entraînement sur DONNÉES (retenue) ✅

- Remplacer/étendre le critère `RBURST` par une comparaison 128-bit complète :
  écrire un motif connu, relire à chaque réglage `(rclkpos, rclksel)`, choisir le
  réglage avec match intégral (idéalement avec marge : premier/dernier réglage qui
  passe → prendre le milieu = œil de données, comme les vrais contrôleurs DDR
  avec MPR/eye-search).
- Robuste aux extensions et modifications futures (AXI, 2048Mb, HW réel) : c'est le
  seul critère qui prouve ce qu'on veut vraiment (« les 8 wagons sont là »).
- Travail : boucle de training dans `READ_CALIB` (ou bring-up), + asserts formels
  associés (cohérence motif écrit/lu).

**Décision : option 2.**

## Résolution du bug 3 — 03/10/2026 (simu 8/8 OK, `SPINAL SIM: ALL TESTS PASSED`)

Mesures VCD (pas de théorie) + itérations, sur la machine rapide (~10 min/simu) :

1. **Q1 tranchée : la fenêtre PEUT couvrir la rafale.** `dqs_en` 18.75 ns wide
   (pulse `dqs_read` 2 pclk) couvre préambule + 4 périodes DQS (11.25 ns),
   `WPOINT` +5. Pas de plafond <10 ns.
2. **Vrai plafond : 1 rafale = ~5 slots FIFO.** `WPOINT` suit les fronts DQS
   (préambule + 4 périodes) alors que la lecture échantillonne 8 taps → max
   structurel ~5-6/8 en simple burst (mesuré : score max 6).
3. **Gate `RBURST` mort par construction.** `dqs_en` reste collé à 1 après la
   rafale (aucun front DQS pour y clock-er `rd_en=0`), et `RBURST` exige
   `~dqs_en` → abandonné au profit du seul score de données.
4. **Double-burst** (2 READ dos-à-dos tCCD, sans auto-precharge + `PRECHARGE`
   explicite, en `READ_CALIB` comme en `READ`) : rafale 1 → slots gray
   `{1,3,2,6,7}`, rafale 2 → `{5,4,0,1,3}` = 8 slots frais, un seul
   échantillon. Fenêtre `dqs_read` 4 pclk (~40 ns) pour couvrir les 2 rafales.
5. **Rotation stable, pas réglage magique.** Le remplissage double-burst est
   une rotation pure des beats (mesuré rot=6 sur tout le sweep). Le sweep
   **score les 8 rotations** et verrouille `bestRot`, appliqué au `rsp`
   (auto-adaptatif, pas de constante en dur).
6. **Dérive de rotation éliminée (rot 4 → 2 entre reads).** Cause VCD :
   `dqs_en` qui monte avec `DQSIN` en Hi-Z fait `DQSR90 : 0→X` (= front
   montant Verilog) qui pré-arme `wpt_q` → le préambule latche un cran bonus.
   Que ça arrive dépendait de `dqs_en` retombé ou non depuis l'accès précédent.
   Fix : `dqs_read` aussi asserté en `WRITE` → `dqs_en` ne retombe plus jamais
   après l'init (ne monte que sur `DQSIN` piloté) → zéro pré-armement, rotation
   identique calib→fonctionnel. Tentative intermédiaire (HOLD tardif cycles
   4-6) revertée : gelait `clk_rd` et tuait la fenêtre.
7. **Détails qui comptent :** latch du training au même cycle que `data_ready`
   fonctionnel (le pointeur de lecture tourne en continu), `HOLD` par itération
   de calib (départ W/R déterministe), `P7/P14` formels MAJ (BL8 sans AP +
   2e burst ; `P3` suit la dé-rotation).

Résultat : `lock (0,0) rot=6 score=8`, **8/8 `READ OK`** (4 blocs × 2 phases,
dont après refreshes), zéro violation timing Micron, `tWLH/tWLS` bénins
(présents aussi en baseline). Reste : preuve formelle du RTL final + validation
HW (memtest UART, la rotation silicium peut différer — le sweep auto s'adapte).

## Suites 03/10/2026 — HW FAIL + faux verrouillage (EN COURS)

- **Symptôme HW** (Tang Primer 20K, UART) : `[DDR3-OK] W=0A P=2 S=0` puis
  `[FAIL] A=0 E=0123... G=7B07FF0610051004 H=...` — des beats du **training**
  (`1004/1005`) dans une lecture fonctionnelle = FIFO rassis, pas bruit UART
  (registres `errActual`, stables et structurés).
- **Cause : faux 8/8 sur données auto-capturées.** La fenêtre toujours ouverte
  auto-capture le strobe d'écriture (loopback `DQSIN`) : le training-write
  remplit le FIFO avec le training. Un réglage à fenêtre ratée latche ce rassis
  → score 8 → verrou faux. En simu le 1er 8 (genuine, `(0,0)`) masquait le
  problème ; sur silicium (autre timing) le sweep tombe sur le faux.
- **Fix : poison-write** (`needPoison`) — après le training-write (bloc 0),
  écriture du complément (`~trainPat`) en bloc 1, même path WRITE. Le sweep
  démarre sur rassis-poison : fenêtre ratée → score 0 (rejet correct),
  fenêtre pleine → training frais → 8. Bonus : le poison-write monte `dqs_en`
  proprement (strobe défini) avant le sweep.
- **Fix incident : `rcalib_done` après le sweep-2.** Il se levait dès le sweep-1,
  donc le trafic utilisateur (et le test AXI) démarrait mid-calibration.
  Maintenant gated par `!training`. Effet de bord qui prouve le point : ça a
  débloqué `Ddr3Axi4Test` (B timeout) — le bridge attendait un core occupé.
- **Visibilité HW : bannière `[DDR3-OK] W=.. P=.. S=.. R=r C=c`** (`best_rot`,
  `best_score` exposés Core→Controller→Axi4→TesterTop→engine). Indispensable
  pour distinguer verrou faux (C<8) de vraie capture sur silicium.
- **Tests unitaires Scala verts** (`mill ddr3.test`, Verilator) : Core (init +
  write/read 128-bit + dé-rotation), Axi4 (bridge 64-bit bout-en-bout),
  TesterTop (memtest autonome + UART). Requis pour ça : `setup.bat` installe
  **w64devkit** 2.9.1 (sh/make/gcc pour Verilator, `tools/w64devkit`), PATH via
  `build.mill` (repo-local d'abord) ; timeouts init 500→3000 (calib complète
  ~1100+ cycles) ; harness TesterTop connecte les nouveaux ports engine.
